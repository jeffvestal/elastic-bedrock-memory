What made this architecture work

Key Design Decisions

[ 01 ]

semantic_text + Jina

No embedding pipeline to maintain. One field type — auto-vectorized at ingest. Drop the field in the mapping, ship data, search semantically.

Zero-pipeline
[ 02 ]

Agent Builder as MCP Server

No custom proxy, no middleware. Point your IDE's MCP config directly at Elastic. The platform IS the MCP endpoint.

No proxy
[ 03 ]

ES|QL + Semantic Search

Structured recall and fuzzy recall from the exact same store. Filter by session. Rank by meaning. One query language, one index.

Hybrid recall
[ 04 ]

Three-Index Schema

Conversation turns, extracted facts, session metadata — each index is independently queryable. No single blob to decompose at read time.

Composable
[ 05 ]

Kiro + Bedrock via MCP

Wired through standard MCP JSON config. No credential ceremony beyond what the IDE already manages. Any MCP-compatible client works.

Standard MCP
